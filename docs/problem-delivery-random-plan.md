# 문제 제공 및 랜덤 로직 기획서

> 상태: 1차 구현 반영
>
> 현재 구현 범위: 카드 CRUD, 문제 CRUD, 설정 개수 기반 랜덤 문제 제공
>
> 채점, 학습 기록, 새로고침 후 진행 복원은 구현하지 않는다.

확정된 요구사항:

- 랜덤 문제는 한 문제만 뽑지 않는다.
- 사용자가 설정한 개수만큼 한 번에 뽑아 문제 묶음을 만든다.
- 같은 묶음 안에서는 문제가 중복되지 않는다.

## 1. 목적

카드 안에 저장한 문제를 어떤 순서와 단위로 보여줄지 정하고, 랜덤 학습에서 같은 문제가 지나치게 반복되는 일을 막는 기준을 세운다.

고정 조건은 다음과 같다.

- 문제는 사용자가 직접 만든다.
- 문제는 하나의 카드에 속하고 `주제` 값을 가진다.
- 채점, 점수, 정답률은 제공하지 않는다.
- 계정, Redis, 여러 사용자 간 상태 공유는 고려하지 않는다.
- 랜덤 문제 제공 외의 학습 기능은 별도 승인 없이 추가하지 않는다.

## 2. 문제 제공 방식 후보

| 방식 | 동작 | 장점 | 한계 | 제안 우선순위 |
| --- | --- | --- | --- | --- |
| 목록에서 직접 선택 | 문제 목록에서 원하는 문제의 답을 펼쳐 본다. | 가장 단순하며 현재 CRUD 화면만으로 가능하다. | 학습 순서를 앱이 정해 주지 않는다. | 현재 제공 |
| 설정 개수만큼 무작위 추출 | 사용자가 개수 `N`을 설정하면 조건에 맞는 문제를 중복 없이 최대 `N`개 뽑는다. | 공부할 분량을 직접 정할 수 있고 한 묶음 안에서 문제가 반복되지 않는다. | 새로운 묶음을 만들면 이전 묶음의 문제가 다시 포함될 수 있다. | 첫 학습 기능 추천안 |
| 전체를 섞어 한 바퀴 풀기 | 시작할 때 문제 전체를 섞고 한 문제씩 차례로 보여 준다. | 한 바퀴 안에서는 모든 문제를 볼 수 있다. | 문제 수가 많으면 원하는 분량보다 길어질 수 있다. | 추가 방식 후보 |
| 등록 순서대로 풀기 | 오래된 문제 또는 최신 문제부터 순서대로 보여 준다. | 결과를 예측할 수 있고 누락이 없다. | 랜덤 학습 목적과는 다르다. | 사용자 선택 필요 |

문제 범위는 제공 방식과 별도로 정한다.

- 카드 전체
- 특정 주제 하나

여러 주제를 동시에 선택하는 기능은 초기 범위에서 제외하는 것을 추천한다.

## 3. 구현된 첫 흐름

아래 흐름을 첫 구현 범위로 반영했다.

1. 카드 상세에서 `문제 풀기`를 누른다.
2. 카드 전체 또는 주제 하나를 범위로 선택한다.
3. 이번에 제공받을 문제 개수 `N`을 설정한다.
4. 해당 범위에서 문제를 중복 없이 최대 `N`개 무작위로 뽑아 하나의 문제 묶음을 만든다.
5. 묶음의 문제를 한 개씩 보여 주고, 사용자가 원할 때 정답·해설을 펼친다.
6. `다음 문제`를 누르면 현재 묶음의 다음 문제를 보여 준다.
7. 뽑힌 문제를 모두 확인하면 완료 상태를 보여 주고, 같은 설정으로 다시 뽑을 수 있게 한다.

채점이 없으므로 `정답`, `오답`, `점수` 버튼은 두지 않는다.

대상 문제가 설정한 개수보다 적으면 중복으로 채우지 않고, 존재하는 문제만 모두 제공한다. 예를 들어 문제를 20개로 설정했지만 해당 범위에 12개만 있다면 12개를 제공하고 그 이유를 화면에 안내한다.

## 4. 랜덤 로직 추천안

### 4.1 기본 원칙

- 문제 묶음을 시작할 때 설정한 개수만큼 한 번에 조회한다.
- 같은 묶음 안에서는 같은 문제를 다시 제공하지 않는다.
- 설정 개수가 대상 문제 수보다 크면 대상 문제 수까지만 제공한다.
- 새로운 묶음은 독립적으로 다시 추출하므로 이전 묶음의 문제가 포함될 수 있다.
- 보안용 난수가 필요한 기능이 아니므로 일반적인 균등 셔플이면 충분하다.

### 4.2 추출 방식

현재 백엔드는 조건에 맞는 DB 행을 무작위로 정렬한 뒤 설정한 개수만큼 한 번에 반환한다.

```text
대상 카드와 선택 주제로 문제 범위 제한
→ DB 무작위 정렬
→ LIMIT requestedCount
→ 반환된 배열을 프론트엔드 문제 묶음으로 저장
→ 배열 인덱스를 한 칸씩 이동하며 표시
```

한 DB 행은 한 번의 조회 결과에 한 번만 포함되므로 문제 묶음 안에서 ID가 중복되지 않는다. 개인용 초기 규모에서는 이 방식을 사용하고, 데이터가 커져 성능 문제가 확인될 때만 다른 추출 방식을 검토한다.

### 4.3 API 호출 방식

현재 `GET /cards/{card_id}/problems/random`은 `limit` 값만큼 DB에서 무작위로 문제를 조회한다. 한 번의 응답 안에서는 중복되지 않으므로, 설정한 문제 개수를 `limit`으로 전달해 하나의 문제 묶음을 만들 수 있다.

```text
GET /cards/{card_id}/problems/random?limit={설정한_개수}
GET /cards/{card_id}/problems/random?topic={주제}&limit={설정한_개수}
```

현재 `limit`은 1부터 100까지 허용한다. 새로운 묶음을 요청할 때 이전 결과는 기억하지 않으므로 묶음 간 중복은 허용된다. 묶음 간 중복까지 막는 기능은 학습 이력 범위가 되므로 초기 추천안에서는 제외한다.

## 5. 진행 상태 저장 후보

개인용 초기 버전은 서버 세션이나 Redis 없이 브라우저에서 관리할 수 있다.

저장할 최소 상태:

```text
cardId
topic 또는 null
설정한 문제 개수
추출된 Problem 배열
현재 cursor
```

| 저장 위치 | 새로고침 | 브라우저를 닫은 뒤 | 복잡도 |
| --- | --- | --- | --- |
| React 메모리 | 초기화 | 초기화 | 가장 낮음 |
| `sessionStorage` | 유지 | 보통 초기화 | 낮음 |
| `localStorage` | 유지 | 유지 | 낮음 |
| DB 학습 세션 | 유지 | 유지 | 높음 |

현재 구현은 React 메모리에서만 진행 상태를 관리한다. 모달을 닫거나 페이지를 새로고침하면 진행 상태가 초기화되며, 브라우저 저장소나 DB에는 기록하지 않는다.

## 6. 데이터 변경 시 현재 처리 기준

| 상황 | 처리 |
| --- | --- |
| 학습 중 다른 화면에서 새 문제 생성 | 현재 문제 묶음에는 넣지 않고 다음 추출부터 포함 |
| 학습 중 다른 화면에서 문제 삭제 | 현재 묶음은 시작 시 받은 내용을 유지하고 다음 추출부터 제외 |
| 학습 중 다른 화면에서 문제 수정 | 현재 묶음은 시작 시 받은 내용을 유지하고 다음 추출부터 변경 내용 반영 |
| 주제 이름 수정 | 현재 묶음은 시작 시 받은 주제를 유지 |
| 대상 문제가 0개 | 시작하지 않고 문제가 없다는 안내 표시 |
| 대상 문제가 설정 개수보다 적음 | 존재하는 문제만 제공하고 실제 제공 개수를 안내 |

현재 랜덤 API는 한 번에 최대 100개를 반환하므로 문제 개수 설정도 우선 1~100 범위로 제한한다. 100개를 넘는 문제 묶음이 실제로 필요해지면 API 제한과 제공 방식을 별도로 재검토한다.

## 7. 첫 구현에서 정한 사항

첫 구현은 다음 기준으로 동작한다.

1. 문제 개수에 기본값을 넣지 않고 사용자가 1~100 사이의 정수를 직접 입력한다.
2. 기본 문제 범위는 카드 전체이며, 필요한 경우 특정 주제를 선택한다.
3. 문제 묶음을 한 번 요청하고 프론트엔드에서 배열 순서대로 보여 준다.
4. 새로고침 후 진행 상태는 복원하지 않는다.
5. 문제 묶음을 완료해도 자동으로 다시 뽑지 않는다.
6. 사용자가 `같은 설정으로 다시 뽑기` 또는 `설정 변경`을 직접 선택한다.

## 8. 초기 제외 범위

- 자동 채점과 정오답 판정
- 점수, 정답률, 통계
- 오답 노트와 가중치 랜덤
- 간격 반복 학습
- 타이머
- 계정별 학습 기록
- Redis 또는 별도 작업 큐

위 기능은 별도 요청과 기획 없이 추가하지 않는다.

## 9. 구현 및 검증 순서

1. 기존 랜덤 API의 설정 개수·주제 범위 동작 확인
2. 문제 범위와 개수를 입력하는 설정 화면 구현
3. 문제·답 확인과 완료 화면 구현
4. 빈 카드, 설정 개수보다 적은 문제, 삭제된 문제, 묶음 안의 중복 방지 검증
5. 사용자 확인 후 다음 범위 결정
